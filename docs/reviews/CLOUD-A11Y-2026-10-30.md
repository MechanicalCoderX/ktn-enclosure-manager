# Cloud accessibility and UI pass, 2026-10-30

Branch `cloud/a11y`. It already existed on origin at `988e309`, which is
current `main` and includes `b8663c2`, so the work builds on that commit
rather than resetting the branch. No PR, no deploy.

Scope: the React frontend (bay grid, Identify controls, tabs, change-password
dialog, login, diagnostics). Checked for keyboard access, visible focus, ARIA
roles and names, and colour contrast in Light, Dark and System. Only
serious or critical axe findings and clear keyboard or focus defects were
fixed. Everything else is listed under follow-ups.

## axe-core 4.14, before and after

Tags: wcag2a, wcag2aa, wcag21a, wcag21aa and best-practice. Screens scanned:
the drive map with Bay 1 selected, Chassis, Diagnostics, the change-password
dialog, and Login. The "before" scan used the desktop viewport; "after" is
the committed test, run in both desktop and mobile.

| Theme | Serious + critical, before | After |
|---|---|---|
| Light | 3 rules, 18 elements | 0 |
| Dark | 3 rules, 18 elements | 0 |
| System (OS dark; OS light in the test) | 3 rules, 18 elements | 0 |

The three rules before:

- `aria-allowed-attr` (critical, 16 elements): `aria-pressed` on
  `<button role="listitem">`.
- `select-name` (critical, 1): the raw-page select had no label.
- `scrollable-region-focusable` (serious, 1): the diagnostics `<pre>` could
  not be reached by keyboard.

Fixing the tile roles exposed a fourth rule:

- `label-content-name-mismatch` (serious, WCAG 2.5.3, 16 elements): the
  tile's `aria-label` did not contain its printed text.

That is fixed too. A fifth showed up only on the mobile viewport:

- `scrollable-region-focusable` (serious, 6 elements): the chassis tables
  overflow sideways on a phone and could not be scrolled by keyboard.

That is fixed as well.

Moderate and minor findings went from 4 rules (27 elements, counted per
screen) per theme to 3 rules (11 elements), all left as follow-ups:

- `page-has-heading-one` on every screen.
- `landmark-one-main` and `region` (6 elements) on Login.
- The minor `aria-allowed-role` on the tiles is gone.

The theme check for text contrast found no failures before and none after.

## Tests added (`frontend/e2e/app.spec.ts`)

These run inside the existing `theme contrast` block. Each runs for 4 modes
(Light, Dark, System with OS light, System with OS dark) and in both projects:

- **axe finds nothing serious or critical on any screen.** Covers the drive
  map with a bay selected, Chassis, Diagnostics after Run (with both `<pre>`
  blocks), the dialog, and Login.
- **Every keyboard focus ring reaches 3:1 against its surface (WCAG
  1.4.11).** The measurement is taken in code, from the outline colour
  composited with ancestor opacity against the painted parent. It covers 15
  targets: tab, search, theme select, freshness summary, a plain, a selected
  and a dimmed tile, the Identify select and button, a chassis table, the diagnostics output,
  the raw-page select, and the dialog's field, primary and secondary buttons.
  A missing ring counts as 0.
- The existing text-contrast passes already measure the changed areas
  (tiles, the new "Page" label, the dialog, the notices). They pass
  unchanged.

There is also a new `keyboard` block:

- The dialog keeps focus through 8 Tabs, closes on Escape and returns focus
  to its opener.
- A tile is selected with Enter and Space, and `aria-pressed` follows.

**Mutation check.** I ran the ring test against the pre-fix CSS and dialog
code. It failed on the summary (no ring) and the dimmed tile (1.61:1 light,
1.85:1 dark), as expected.

**Full Playwright run** (desktop and mobile) at `a600068`: 95 passed,
5 skipped (project gates), 0 failed. Before this pass the suite had 80
tests; it now has 100.

The first full run, before `a600068`, failed in two places:

- Mobile axe found the table issue described above.
- `identify expiry … (server clock ahead)` failed once on mobile ("expected
  exactly one bay poll in one poll interval", got 2). That test is
  timing-based and does not touch the changed code. It passed on the
  targeted rerun and on the final full run, so treat it as a possible flake
  to watch.

## Follow-ups (not built)

1. **Identify and Clear lose focus.** Each button disables itself while
   busy, and focus drops to `<body>`. The dialog buttons do the same. Fix:
   `aria-disabled` plus a guard in the handler.
2. **Tabs pattern is incomplete.** There is no `tabpanel` or
   `aria-controls`, no roving tabindex and no arrow-key support, and
   `<nav role="tablist">` overrides the nav landmark.
3. **Use a native `<dialog>` with `showModal()`.** It would replace the
   hand-made inert, Escape and focus-return code.
4. **Make the bay shelf a single Tab stop.** Today it is 16 stops; arrow
   keys with a roving tabindex would cut that to one.
5. **Add an `<h1>` and a `main` landmark on Login.** These are the
   remaining moderate axe findings.
6. **Search results are shown only by dimming.** Add a live match count and
   a "no match" state on each tile.
7. **Freshness popover.** It does not close with Escape or a click outside.
8. **Windows High Contrast.** The selected tile's `box-shadow` ring
   disappears. Add an `@media (forced-colors: active)` border.
9. **Add a dedicated `--focus` token.** The ring currently shares
   `--accent` with filled buttons and selected tiles.
10. **"Copy diagnostics" gives no feedback,** and does nothing silently over
    plain HTTP.
11. **Live regions for poll warnings.** The `.notice.warn` degradation
    banners could take `role="status"`.

## Environment notes

- The project pins Playwright 1.64.1, which expects Chromium revision 1248.
  The image ships revision 1243, so the tests ran with
  `PLAYWRIGHT_BROWSERS_PATH` pointing at a symlink to the preinstalled
  revision. Nothing in the repo changed for this.
- In `package-lock.json`, only the `@axe-core/playwright` and `axe-core`
  entries were added. This npm version also wanted to drop unrelated
  `libc` fields; those changes were not kept.
